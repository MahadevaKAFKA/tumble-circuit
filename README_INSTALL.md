## 1. Quick start — no extra tools (recommended for the first playtest)

1. Open **Roblox Studio** → **File → Open from File…** → choose `TumbleCircuit.rbxlx`.
2. The world looks empty in edit mode. That is expected: the course is **generated by script**
   when the game starts.
3. Press **Play** (F5). Within a second or two you should see the night-sky course, the title
   screen and your marble on the start pad behind it.
4. Click **PLAY**. You are on the Orbital Garage hub: roll down the practice chute while the board
   counts down. The next race starts automatically (15 s intermission, 3-2-1-GO). After the race,
   results appear and the next round follows. For two players use the Test tab (TEST_PLAN §5).
5. Open **View → Output** to see `[TumbleTests] … passed, … failed` lines from the built-in tests.

`TumbleCircuit.rbxlx` is produced from the Rojo project by `tools/build_rbxlx.py` (a small
builder written for this project). If you change source files, rebuild it (step 2) or use Rojo.

## 2. Rojo workflow (source of truth)

The Rojo project is `default.project.json`; all code lives in `src/`.

1. Install Rojo 7.x and its Studio plugin: <https://rojo.space/docs/v7/getting-started/installation/>
   (for example via Rokit/Aftman, or the GitHub release binary).
2. Either build a place file:
   ```
   cd TumbleCircuit
   rojo build default.project.json -o TumbleCircuit.rbxlx
   ```
   or live-sync into an open place:
   ```
   rojo serve
   ```
   then press **Connect** in the Rojo plugin inside Studio.
3. Without Rojo you can still rebuild the place file with Python 3:
   ```
   python3 tools/build_rbxlx.py . TumbleCircuit.rbxlx
   ```

Mapping (`default.project.json`):

| Studio location | Source |
|---|---|
| ReplicatedStorage.Shared | `src/ReplicatedStorage/Shared/*` + `PLACEHOLDER_IDS.lua` as `PlaceholderIds` |
| ServerScriptService.ServerBootstrap | `src/ServerScriptService/ServerBootstrap.server.lua` |
| ServerScriptService.Services | `src/ServerScriptService/Services/*` |
| ServerScriptService.Tests | `src/Tests/*` |
| ServerStorage.ProceduralBuilders | `src/ServerStorage/ProceduralBuilders/*` |
| StarterPlayer.StarterPlayerScripts | `ClientBootstrap.client.lua` + `Controllers/*` |
| Players / StarterPlayer / Workspace | `CharacterAutoLoads=false`, `EnableMouseLockOption=false`, `StreamingEnabled=false` |

If you `rojo serve` into an existing place, the server still forces `CharacterAutoLoads=false`
at startup, and marbles keep streaming focus via `ReplicationFocus`, so the property values are a
convenience rather than a requirement.

## 5. Key decisions (short version — details in BUILD_STATUS.md)

- **Authority:** client network ownership of each player's marble; the server spawns, freezes,
  releases, judges checkpoints / finish / placement from observed positions and audits movement.
  Bots are server-owned and run the same motor module. Everything that matters (rewards, gates,
  votes, cooldowns) is decided on the server; no remote can grant or set anything.
- **Avatar:** no Character, no Humanoid — one radius-2 Ball per racer, fresh at every spawn.
- **Hazards:** pure functions of (seed class, server time − GO); no per-frame hazard traffic.
- **Saving:** DataStore with session locking on live servers; an in-memory mock in Studio unless
  you set `GameConfig.Persistence.StudioMode = "Live"` in a throwaway test universe.
- **Sound:** silent. Fill ids in `PLACEHOLDER_IDS.lua` once you have licensed audio.

## 6. Tuning

Edit and press Play again:
- Feel: `src/ReplicatedStorage/Shared/PhysicsConfig.lua` (accel 35, lateral cap 22, terminal 80,
  air control 40 %, brake ×0.65, deadzone 0.12, plus drag/rolling resistance).
- Camera/UI: `GameConfig.lua`.
- Course length, slopes, banking, hazards, gates: `TrackDefinitions.lua` (`NeonFoundry`; the
  validator prints a warning in Output if a change makes the course unsafe; regenerate
  ROUTE_MAP.md with `texlua tools/offline/route_map.lua . > ROUTE_MAP.md`).
- Bots: `RaceConfig.Bots` (FillTo, kill switch). Rewards / levels: `ProgressionConfig.lua`.
  Vote / emotes: `SocialConfig.lua`. Soak test: `GameConfig.Debug.SoakMinutes = 15`.

## 7. Offline tests (no Studio needed)

```
texlua tools/offline/run_tests.lua .
```
Syntax-checks every file and runs the pure specs. `texlua` ships with TeX Live; any Lua 5.3
interpreter with LuaFileSystem works.

## 8. Troubleshooting

- **"Could not start practice…" on screen:** open Output and look for `[TrainingTrack]` or
  `[TumbleCircuit]` warnings; press Stop and Play again.
- **Blank grey world, nothing happens:** the scripts did not load. Rebuild the place (section 2)
  and check that `ServerScriptService.ServerBootstrap` exists.
- **A normal Roblox avatar appears:** another script is calling `LoadCharacter`. The marble
  service removes it and logs `[Marble] removing unexpected Character`.
